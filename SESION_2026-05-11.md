### 2. `src/processing/data_cleaner.py` ✅ NUEVO
**Qué hace:** Loop interactivo de limpieza guiada — el usuario decide qué hacer con cada problema.

**Flujo:**
```
CleaningSession.start(report)
```

### 4. `src/processing/attribution_parser.py` ✅ NUEVO
**Qué hace:** Explota celdas multi-valor de atribución antes de que el planner vea el df.

**Agnóstico real:** No asume Meta, Google, TikTok, ni ninguna jerarquía.
- Separador: detectado por frecuencia en el dato
- N partes: detectado del máximo observado
- Nombres: `p1, p2, p3` por defecto (posición, siempre correcto)
- Nombres custom: `ADLY_ATTRIBUTION_LEVELS=campaña,adset,creativo` en `.env` (opcional)

**Resultado en CSV de Camí:**
```
'ad primera atribucion' → 3 partes:
  ad_primera_atribucion__p1  (campaña)
  ad_primera_atribucion__p2  (adset)
  ad_primera_atribucion__p3  (creativo)
```

**Firma pública:**
```python
result = parse_attributions(df)
result.df              # df con columnas nuevas
result.columnas_nuevas # list[str]
schema_para_planner(result)  # str inyectable al prompt
```

## Bugs pendientes (próxima sesión)

### 🔴 Crítico
1. **`attribution_parser` no conectado al df del planner** — el planner agrupa `"LATAM BUSINESS CREDIT | WhatsApp Leads | HOOK MONEY FAST"` como string completo. Integrar `parse_attributions()` en el pipeline de carga o en el engine antes de cada query.

2. **Dos normalizadores con vocabularios distintos — conflicto de stages** — `ingestion_normalizer` mapea `"Closed Won" → "Cerrado Ganado"` pero `value_mapper` mapea `"Closed Won" → "venta"`. Los comandos `/cohorts`, `/rentabilidad`, y `/velocidad` usan el vocabulario canónico de Adly ("venta") pero el df tiene "Cerrado Ganado" del normalizador. Rompe todos los comandos de análisis de conversión.
   ```
   /cohorts → ⚠ No se detectaron valores de venta en 'stage'
   ```
   **Solución:** unificar en un solo vocabulario. Opciones:
   - Hacer que `ingestion_normalizer` use el vocabulario de `value_mapper` (canónico)
   - O hacer que los comandos detecten ambos vocabularios dinámicamente
   - Recomendado: opción 1 — eliminar `STAGE_MAP` de `ingestion_normalizer` y usar `ValueMapper` directamente

### 🟠 Alto
3. **`/columnas` muestra flags de Adly mezclados con columnas del negocio** — el usuario ve 15 columnas cuando solo hay 9 de datos. `cmd_columnas` necesita filtrar con `_es_columna_flag()` igual que `DataQualityReport`.

4. **Engine no redirige cuando falta columna de costo** — responde "$0 de inversión" en vez de preguntar si analiza por volumen de leads. Mejorar el sistema prompt o agregar lógica de detección de columnas faltantes.

### 🟡 Menor
5. **Prints de debug activos** — `[PLANNER]`, `[SANDBOX]`, `[VALIDADOR]`, `[CHAT]` en `query_engine.py` y `chat.py`. Limpiar antes de demo con Camí.

6. **Rate limit de Groq** — latencia alta por fallback a Gemini en cada request. Solución aplicada en sesión: `/modelo gemini`. Pendiente: configurar Gemini como principal en `.env` por defecto.
